## 継続収集機能の候補

検討段階・未実装。優先度は中の先頭。初回公開の必須条件にはしない。採用時期と操作仕様は未確定。

関連タスク（本機能とセットで検討）:

- MutationObserver による動的画像追加の検知（SPA の対応範囲は未確定）
- debounceによる追加画像のバッチ処理（300msは初期候補。間隔は負荷と操作感を確認して決める）

### 目的・利用場面

拡張アイコン押下時の画像抽出に加え、その後に元ページで読み込まれた画像も同じ viewer に追加する。元タブでスクロールして画像を読み込ませ、別タブまたは別ウィンドウの一覧でまとめて確認できるようにする。

### 想定する動作

- 初回抽出後、元ページの要素追加や `src` / `srcset` などの属性変更を MutationObserver で監視する。
- URL を正規化して既存一覧との重複を除き、追加分を短い間隔でまとめて送る。
- background は抽出元タブとセッションを紐づけ、新しい viewer を毎回開かず、既存一覧へ追記する。
- viewer は追加画像を末尾に表示する。スクロール位置・適用中のフィルター・表示中の拡大／原寸画像を維持し、件数を更新する。
- 同じセッションの複製 viewer にも追加画像を反映する。
- 自動スクロールは行わず、ユーザー操作によってページ側が読み込んだ画像を収集する。DOM 変更を伴わない CSS 画像の変化などは別途検討する。

### 実装量を抑える初期案（未決定）

- 元タブにつき収集中のセッションは1つとし、収集中にアイコンを再クリックした場合は既存 viewer を表示する。
- 元ページの移動・終了、または最後の参照 viewer の終了で監視を停止する。SPA 内の画面遷移をどう扱うかは別途決める。
- 画像追加が一定時間途切れたら停止する案（旧仕様案では5秒）も未決定。スクロールを再開した場合の取りこぼしを考慮し、停止・再開操作と合わせて判断する。
- 収集中／停止中の状態を表示し、停止操作を用意する。
- アイコン押下から監視するか、現行の一括抽出を既定として viewer から任意で開始するかは実装前に決める。停止後の再開と、停止中に増えた画像の扱いも検討する。

### 実装・検証上の注意

- 変更規模は中程度を想定。DOM 監視だけでなく、追加配信・セッション管理・終了処理まで変更が必要。
- 追記と参照登録／解除が競合しないよう、既存のセッション操作キューとの整合性を保つ。終了後の遅延メッセージで削除済みセッションを復活させない。
- 最大1500件の上限と保存失敗時のフォールバックを継続収集にも適用する。上限到達時の通知と収集停止の扱いを決める。
- ページの大量更新時にも過剰な再走査や送信を避け、監視停止時には Observer と送信待ちタイマーを片付ける。
- 遅延読み込み、連続追加、URL重複、複製 viewer、viewer のF5、元タブの移動・終了、最後の viewer 終了を検証する。
- 追加する状態表示・操作文言は英語／日本語の両方に対応する。

## 通信監視モードの候補

公開後の機能候補・未実装。DOM監視による継続収集を先に進め、その後に通信監視を試作する。採用・実装方式・追加権限は未確定。初回公開の範囲には含めない。

### 目的と今回確認した制限

- 現在は通常のDOM内の `<img>` とCSS背景画像からURLを抽出する。通信だけに現れる画像URLや、canvasの描画内容は収集しない。
- 現在の探索はShadow DOMの内部へ入らない。openなShadow DOM内の画像要素を探索する対応は、別途検討が必要。
- 提示されたFlutterのHTML断片では、openなShadow DOM内にcanvasがあり、画像URLを持つ `<img>` はなかった。Shadow DOM対応だけを追加しても、canvasから元画像URLは取得できない。DOM監視もcanvasの描画更新だけでは画像URLを検出できない。
- ユーザーの通信調査では、通常の画像フィルターには現れなかったサムネイルの署名付きURLが全通信から見つかった。Fetch/XHRなどで取得して描画している可能性はあるが、通信種別は未確認。原寸画像の取得可否と、取得したURLをViewerで表示できるかも未検証。
- canvasの描画結果の書き出しは元画像URLの収集とは別機能であり、通信監視とは分けて検討する。

### 想定する操作と検証事項

- 利用者が対象タブで明示的に開始・停止するモードを候補とする。開始後にページをスクロールしたり画像を開いたりして発生した通信から、画像URLを収集する。
- 開始前に読み込み済みの画像は拾えない可能性がある。キャッシュ、画像の再表示、ページ再読み込み時の監視継続を検証し、必要な操作を決める。
- DOM監視と、既存Viewerへの追記・重複除外・複製Viewerへの反映・1500件上限・保存失敗時の処理を共通化できるか検討する。
- ページ移動・元タブ終了・最後のViewer終了時の停止と、監視中であることの表示を設計する。
- 画像以外の通信や不要な画像を除外する方法、対象タブへの限定、表示負荷を検証する。具体的なAPIや取得方式は実験後に決定する。
- 署名付きURLの有効期限切れ、配信元の認証・表示条件、サムネイルと原寸画像の違いを確認する。監視でURLを検出できても表示できるとは限らない。
- 必要な権限、ストア申告、日英プライバシーポリシーへの影響を採用前に確認する。現行版の権限・説明を、未実装の機能に合わせて先行変更しない。

会員ページ固有のURL・画像・認証情報、署名付きURLの全文は、TODO・テスト素材・ログ例・公開Issueに保存しない。検証にはローカルの模擬ページや公開可能な素材を使う。
