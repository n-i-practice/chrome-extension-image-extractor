## 自動テスト

開発用の依存パッケージをインストールした環境で実行する。

```sh
npm test
```

セッション管理だけを指定する場合：

```sh
npm run test:session
```

セッション管理は Node.js 標準のテスト機能と既存の esbuild を使用する。Viewer 操作とフィルターでは、さらに開発用依存の jsdom を使用する。
検証環境は Node.js 24。実際の `src/background/background.ts` をメモリ上でビルドし、Chrome API を模擬した環境へ読み込む。

### セッション管理の対象

- 同時抽出した一覧のセッション分離
- 初回起動・F5 相当の再登録による参照の重複防止
- 複製元／複製先のどちらを先に閉じても残った一覧を保持
- 複製の同時登録による参照の欠落防止
- 最後の複数タブの同時終了と全関連キーの削除
- 複製登録中の元タブ終了
- A を別ウィンドウに残し、複製 A・B・複製 B をまとめて終了
- タブ作成完了前の終了と、その後もキューが処理を継続すること
- 登録中の複製タブの終了
- 無関係なタブの終了・重複する終了通知
- 処理完了後に background を再生成しても保存済みの参照を使えること

保存処理は非同期にし、値を複製して、同じ参照への同時更新を検出できるようにする。
`images:`・`imagesNotice:`・`viewerRefs:`・`viewerTab:` のキー全体を照合する。

このテストは Chrome 本体や Viewer の画面を起動しない。F5 は起動メッセージの再送、ウィンドウ終了は複数の終了イベントで模擬する。
Service Worker の再起動ケースは処理完了後のメモリ初期化を模擬するもので、処理途中の強制停止や Chrome 固有のイベント配信を保証するものではない。

### 複製・再読み込み・Worker再起動の追加確認（2026-10-14）

Chrome 155.0.8059.40を独立した一時プロファイル・headlessモードで起動し、配布ビルドの `dist/` を読み込んで検証した。ユーザーの通常のChromeプロファイルは使用していない。Chrome APIは模擬せず、実際の `tabs.duplicate`・再読み込み・タブ終了・`storage.session` を使用した。

画像抽出は今回の検証対象から外し、ローカルのSVG画像URL2件を確認用のセッションに保存してViewerを起動した。Viewerからの参照登録とbackgroundの参照更新・終了時の掃除は配布コードをそのまま実行した。

- 複製後の参照一覧はタブID2件。複製側を5回再読み込みしても参照一覧の内容・件数は変わらない。
- 元のViewerを閉じると参照は1件になり、画像URL2件は保持される。複製側を再読み込みして画像カード2件が再表示される。
- 最後のViewerを閉じると `storage.session` が空になる。
- 別のセッションで元・複製の2タブを開き、Chrome DevTools Protocolの `ServiceWorker.stopWorker` でWorkerを停止した。実際の状態通知で `stopping → stopped` を確認した。
- 停止後に複製タブを閉じると `starting → running` の再起動を確認でき、参照は1件、画像URLは2件のまま保持された。残ったViewerの再読み込みでも画像カード2件が再表示された。
- 残ったViewerを閉じると `storage.session` が空になることを確認した。

Workerの処理完了後の停止・再起動に対する確認であり、保存処理の途中での強制停止やOS終了による中断は対象外。
