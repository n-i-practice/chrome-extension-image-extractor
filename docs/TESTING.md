# テストの実行と確認項目

## 整備の段階

1. セッション管理：自動テストを追加済み。Chrome での確認手順は下記。
2. Viewer 操作：クリック／ドラッグ、拡大／原寸切り替え、矢印移動、Escape（未着手）。
3. フィルター：条件変更と表示件数・画像移動の整合性（未着手）。
4. 異常系：画像取得・保存・読み込み失敗と通知表示（未着手）。

## 自動テスト

開発用の依存パッケージをインストールした環境で実行する。

```sh
npm test
```

セッション管理だけを指定する場合：

```sh
npm run test:session
```

Node.js 標準のテスト機能と、既存の esbuild を使用する。追加のテスト用パッケージは不要。
検証環境は Node.js 24。実際の `src/background/background.ts` をメモリ上でビルドし、Chrome API を模擬した環境へ読み込む。

### セッション管理の対象

- 同時抽出した一覧のセッション分離
- 初回起動・F5 相当の再登録による参照の重複防止
- 複製元／複製先のどちらを先に閉じても残った一覧を保持
- 複製の同時登録による参照の欠落防止
- 最後の複数タブの同時終了と全関連キーの削除
- 複製登録中の元タブ終了
- A を別ウィンドウに残し、複製 A・B・複製 B をまとめて終了
- タブ作成完了前の終了と、その後もキューが処理を継続すること
- 登録中の複製タブの終了
- 無関係なタブの終了・重複する終了通知
- 処理完了後に background を再生成しても保存済みの参照を使えること

保存処理は非同期にし、値を複製して、同じ参照への同時更新を検出できるようにする。
`images:`・`imagesNotice:`・`viewerRefs:`・`viewerTab:` のキー全体を照合する。

このテストは Chrome 本体や Viewer の画面を起動しない。F5 は起動メッセージの再送、ウィンドウ終了は複数の終了イベントで模擬する。
Service Worker の再起動ケースは処理完了後のメモリ初期化を模擬するもので、処理途中の強制停止や Chrome 固有のイベント配信を保証するものではない。

## Chrome での手動確認

`npm run build` 後、Chrome に `dist/` を読み込むか、登録済み拡張を更新する。
以下は今回の自動テスト追加時には未実施。公開前の確認時に結果を記録する。

保存データは拡張の Service Worker の開発者ツールで確認できる。

```js
chrome.storage.session.get(null).then(console.log)
```

Chrome 全体は終了せず、確認用のウィンドウを残す。ブラウザー終了で session データが消えると、拡張自身による掃除を確認できない。

- [ ] 別々のページから一覧 A・B を開き、画像とセッション ID が混ざらない。
- [ ] 一覧 A を複製して F5 を押す。参照が増殖せず、元を閉じても複製側の画像を再表示できる。
- [ ] 複製側を先に閉じた場合も、元の一覧が使える。
- [ ] ウィンドウ1に A、ウィンドウ2に複製 A・B・複製 B を置いてウィンドウ2を閉じる。A の画像・通知と残ったタブの参照だけが残り、B の全関連キーは消える。
- [ ] 残った A も閉じると、そのセッションの画像・通知・参照・タブ対応表がすべて消える。
- [ ] 一覧を開いてすぐ閉じる操作を繰り返しても不要なキーが残らず、その後も新しい一覧を開閉できる。
- [ ] Service Worker が停止・再起動した後も、複製タブの終了時に残った一覧を保持し、最後の終了時には掃除できる。

画面が閉じることに加えて、「残すべきデータが残る」「最後に不要データが消える」「後続の開閉が動く」の3点を確認する。
