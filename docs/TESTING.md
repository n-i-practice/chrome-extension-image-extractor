# テストの実行と確認項目

## 整備の段階

1. セッション管理：自動テストを追加済み。Chrome での確認手順は下記。
2. Viewer 操作：自動テストを追加済み。Chrome での描画・操作確認は下記。
3. フィルター：自動テストを追加済み。Chrome での入力・表示確認は下記。
4. 異常系：自動テストを追加済み。Chrome での失敗時の確認は下記。

## 自動テスト

開発用の依存パッケージをインストールした環境で実行する。

```sh
npm test
```

セッション管理だけを指定する場合：

```sh
npm run test:session
```

セッション管理は Node.js 標準のテスト機能と既存の esbuild を使用する。Viewer 操作とフィルターでは、さらに開発用依存の jsdom を使用する。
検証環境は Node.js 24。実際の `src/background/background.ts` をメモリ上でビルドし、Chrome API を模擬した環境へ読み込む。

### セッション管理の対象

- 同時抽出した一覧のセッション分離
- 初回起動・F5 相当の再登録による参照の重複防止
- 複製元／複製先のどちらを先に閉じても残った一覧を保持
- 複製の同時登録による参照の欠落防止
- 最後の複数タブの同時終了と全関連キーの削除
- 複製登録中の元タブ終了
- A を別ウィンドウに残し、複製 A・B・複製 B をまとめて終了
- タブ作成完了前の終了と、その後もキューが処理を継続すること
- 登録中の複製タブの終了
- 無関係なタブの終了・重複する終了通知
- 処理完了後に background を再生成しても保存済みの参照を使えること

保存処理は非同期にし、値を複製して、同じ参照への同時更新を検出できるようにする。
`images:`・`imagesNotice:`・`viewerRefs:`・`viewerTab:` のキー全体を照合する。

このテストは Chrome 本体や Viewer の画面を起動しない。F5 は起動メッセージの再送、ウィンドウ終了は複数の終了イベントで模擬する。
Service Worker の再起動ケースは処理完了後のメモリ初期化を模擬するもので、処理途中の強制停止や Chrome 固有のイベント配信を保証するものではない。

## Viewer 操作の自動テスト

`npm run test:viewer` で第2段階だけを実行できる。`npm test` はセッション管理・Viewer 操作・フィルター・異常系の全テストを実行する。

実際の `viewer.html` と `viewer.ts` を jsdom 上で起動し、カード・画像・ボタンのクリックとマウス・キーボードイベントを送る。
Chrome API と画像の読み込み・寸法は模擬し、外部サイトには接続しない。jsdom は開発用依存にだけ追加し、拡張の配布物には含めない。

対象は34ケース：

- サムネ・メタ行からの表示、背景の inert 属性と初回フォーカス
- 読み込み待ち／キャッシュ済み画像の表示と原寸ボタンの状態
- 画像／ボタンによる拡大・原寸切り替え、画面内に収まる画像の扱い
- 拡大・原寸の両状態でのドラッグ後クリック抑止と、4px 境界・次のクリック
- 原寸パンの上下左右の端、片軸だけはみ出す画像、左ボタン以外の押下
- 矢印ボタン・キーでの前後移動、先頭・末尾・1枚だけの場合
- 原寸・ドラッグ・読み込み待ちからの画像移動と状態のリセット
- Alt／Ctrl／Meta 付き矢印の除外、Shift 付き矢印の許可
- 入力欄・編集可能要素での矢印除外と Escape
- 拡大・原寸・読み込み待ちから Escape／閉じるボタン／背景で閉じて再度開く
- 一覧表示中のキー入力とウィンドウサイズ変更

CSS による実際の描画、画像デコード、Tab の移動順序、ブラウザーのショートカットは jsdom では検証しない。
パンの検証では画像の寸法と位置を補い、contenteditable のケースでは `isContentEditable` 判定値を補っている。

- [ ] 原寸でパンでき、端で止まる。ドラッグ直後のクリックで意図せず縮小しない。
- [ ] 拡大表示中のドラッグで原寸に変わらず、次の通常クリックは反応する。
- [ ] 矢印ボタン・左右キーで移動でき、先頭・末尾の矢印が適切に隠れる。

## フィルターの自動テスト

`npm run test:filter` で第3段階の24ケースだけを実行できる。Viewer 操作と同じ jsdom 環境を利用し、追加パッケージは不要。

- 初期の 400×400 条件、境界サイズ、片軸だけ不足する画像
- 入力中と適用済み条件の区別、適用ボタンと幅／高さ欄の Enter
- クリアは入力だけを戻す仕様と、0 による各軸の制限解除
- 空欄・負数・小数の補正と、不正文字入力の抑止
- SVG／GIF の独立した切り替え、サイズ条件との組み合わせ
- 表示件数と元の総数、0件からの復帰、空の一覧
- 非表示画像を除外した前後移動
- 現在画像が残る場合の表示維持と位置の再計算、除外された場合の終了
- 遅れて読み込まれる画像にも確定した条件を適用し、前後移動を同期
- 日本語／英語への切り替え後も条件・入力・件数を維持

画像の読み込み順序を制御して検証する。モーダル表示中の背景は実画面では inert になるため、
条件変更後の同期処理の一部はテストから変更イベントを送って確認する。
ブラウザー固有の数値入力・描画は実機確認に分ける。読み込み失敗と通知は第4段階の対象。

### フィルターの実機確認（未実施）

- [ ] 400px の境界や縦横比の違う画像で、初期条件と表示件数が正しい。
- [ ] 幅・高さを編集しただけでは一覧が変わらず、適用／Enter で変わる。
- [ ] クリア後も適用中の条件は残り、適用すると 0 の条件になる。
- [ ] 空欄・負数・小数・貼り付けを試し、不正な条件が残らない。
- [ ] SVG／GIF とサイズの条件を組み合わせても、表示件数と前後移動が一致する。
- [ ] 全件を非表示にしてから条件を緩めると、画像を再表示して拡大できる。
- [ ] 読み込みの遅い画像が加わっても、確定した条件と拡大中の画像・前後移動が保たれる。
- [ ] 日本語／英語の切り替え後も、入力中の値・適用条件・表示件数が一致する。

## 異常系の自動テスト

`npm run test:failure` で第4段階の29ケースだけを実行できる。
既存の補助環境に API 失敗・画像 error イベント・仮想タイマーを追加し、
実際の background / Viewer の処理を通して確認する。

- 対象タブなし、タブ取得・注入確認・初回注入・注入済みページでの実行失敗
- エラー画面の起動と翻訳、エラー画面自体の作成失敗
- 1500件の上限と1501件の切り詰め、元件数の通知
- 保存失敗時の一時配信、同時セッションの配信先、起動後の一度だけの配信
- 上限超過と保存失敗が重なる場合の画像・通知
- 一覧タブ作成失敗時の掃除、他セッションの保持と後続の抽出
- 作成後の参照登録失敗でエラータブを増やさず、起動通知による再登録と後続操作が動くこと
- 配信失敗時の例外処理、別セッション／別種別のメッセージ除外
- 配信タイムアウト、遅れた配信の無視、成功した0件との区別
- session 読み出し失敗の案内と日本語／英語の切り替え
- 通知の併記、通常・不正な通知の非表示
- サムネ読み込み失敗後の件数・現在画像・前後移動
- モーダル画像の読み込み失敗後の移動・終了操作

保存失敗から配信されるペイロードを別起動した Viewer へ渡すケースも含む。
Chrome 内で background と Viewer を同時起動する E2E テストではない。
API 失敗は模擬しており、Chrome 自体の容量制限や通信・描画を直接検証するものではない。
参照管理の storage API が継続して失敗する場合の復旧や、Service Worker の処理途中での強制停止は対象外。

### テストで見つけて修正した問題

- サムネの失敗でカードを除去した後も、表示件数が古いままになる。
- 一覧タブの作成失敗で、保存データや一時配信待ちデータが残る。
- メッセージ経由の一覧作成・一時配信の失敗が、未処理の例外になる。
- 作成済み一覧の参照登録だけが失敗した場合にも、抽出失敗のタブを追加してしまう。エラー画面の追加は一覧タブの作成失敗時に限定した。
- session 読み出し失敗で案内が出ず、一時配信のタイムアウトが「画像なし」になる。

読み出し・配信待ちの失敗には、元のページから再抽出する案内を英語／日本語で追加した。
表示件数と読み込み中・失敗件数の全面的な整理は、既存TODOの別項目として残す。

- [ ] 読み込みできない画像を含むページで、失敗画像が一覧から消え、表示件数と移動先が一致する。
- [ ] 拡大画像の通信が失敗しても、矢印・Escape・閉じるボタンが使える。
- [ ] 検証用環境で保存失敗を再現し、一時配信の画像と注意書きが表示される。
- [ ] 一時配信が届かない場合、約8秒後に再抽出の案内が表示される。
- [ ] 失敗の案内と通知が日本語／英語の切り替え後も維持される。

## セッション管理の Chrome 手動確認

`npm run build` 後、Chrome に `dist/` を読み込むか、登録済み拡張を更新する。
以下は今回の自動テスト追加時には未実施。公開前の確認時に結果を記録する。

保存データは拡張の Service Worker の開発者ツールで確認できる。

```js
chrome.storage.session.get(null).then(console.log)
```

Chrome 全体は終了せず、確認用のウィンドウを残す。ブラウザー終了で session データが消えると、拡張自身による掃除を確認できない。

- [ ] 別々のページから一覧 A・B を開き、画像とセッション ID が混ざらない。
- [ ] 一覧 A を複製して F5 を押す。参照が増殖せず、元を閉じても複製側の画像を再表示できる。
- [ ] 複製側を先に閉じた場合も、元の一覧が使える。
- [ ] ウィンドウ1に A、ウィンドウ2に複製 A・B・複製 B を置いてウィンドウ2を閉じる。A の画像・通知と残ったタブの参照だけが残り、B の全関連キーは消える。
- [ ] 残った A も閉じると、そのセッションの画像・通知・参照・タブ対応表がすべて消える。
- [ ] 一覧を開いてすぐ閉じる操作を繰り返しても不要なキーが残らず、その後も新しい一覧を開閉できる。
- [ ] Service Worker が停止・再起動した後も、複製タブの終了時に残った一覧を保持し、最後の終了時には掃除できる。

画面が閉じることに加えて、「残すべきデータが残る」「最後に不要データが消える」「後続の開閉が動く」の3点を確認する。
