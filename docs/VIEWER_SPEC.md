## Viewer 仕様書

本ドキュメントは、Chrome 拡張の画像ビューアにおける表示状態、モーダル制御、フィルター機能の仕様を定義する。

---

## 1. 画面構成と状態

viewer は以下の 3 つの状態を持つ。

- grid: 一覧表示
- zoom: 拡大表示
- original: 原寸大表示

状態遷移はユーザー操作に応じて発生し、各状態は以下の関数で制御する。

- enterGridState()
- enterZoomState()
- enterOriginalState()

---

## 2. 状態遷移仕様

### 2.1 一覧 → 拡大表示

イベント:

- 一覧の画像カードをクリックする

処理:

- modal を表示する
- modal-img にクリックされた画像の src を設定する
- viewerState を zoom に変更する
- left / top の位置をリセットする
- 画面サイズに応じて zoom-in アイコンの表示状態を更新する
- zoom-out アイコンは非表示にする

### 2.2 拡大表示 → 一覧

イベント:

- close ボタンをクリックする
- overlay をクリックする
- Escape キーを押す

処理:

- modal を非表示にする
- viewerState を grid に戻す
- left / top を初期化する

### 2.3 拡大表示 → 原寸大表示

イベント:

- zoom ボタンをクリックする
- 原寸表示が意味のある画像（画面より大きい）を modal-img 上でクリックする（ドラッグしていない場合。拡大表示中のドラッグは何もしない）

処理:

- modal-img に original クラスを付与する
- zoom-in アイコンを非表示にし、zoom-out アイコンを表示する
- 画像を画面中央へ配置する
- viewerState を original に変更する
- カーソルを zoom-out にする

### 2.4 原寸大表示 → 拡大表示

イベント:

- zoom ボタンをクリックする
- modal-img 上でクリックする（ドラッグしていない場合）

処理:

- original クラスを取り除く
- left / top を 0 に戻す
- zoom-in アイコンを表示し、zoom-out アイコンを非表示にする
- viewerState を zoom に戻す
- 原寸表示が可能な場合はカーソルを zoom-in にする

### 2.5 原寸大表示 → 一覧

イベント:

- close ボタンをクリックする
- overlay をクリックする
- Escape キーを押す

処理:

- modal を非表示にする
- viewerState を grid に戻す
- left / top をリセットする

---

## 3. ドラッグ動作仕様

オリジナルサイズ表示時に、画像が画面より大きい場合のみドラッグ可能とする。

### 3.1 ドラッグ開始

イベント:

- original 状態で modal-img を mousedown する

処理:

- ブラウザ標準の画像ドラッグを抑止する
- dragging クラスを付与する
- startX, startY を記録する
- 現在の画像位置 imgX, imgY を記録する

### 3.2 ドラッグ中

イベント:

- mousemove

処理:

- dx, dy を計算する
- newLeft, newTop を算出する
- 画像の幅・高さと画面サイズを比較し、ドラッグ範囲を制限する
- modal-img の left / top を更新する

### 3.3 ドラッグ終了

イベント:

- mouseup

処理:

- dragging クラスを除去する
- isDragging を false に戻す
- 閾値以上動いていた場合は、続く click での表示切替を行わない

---

## 4. SVG / GIF フィルター仕様

一覧の画像カードに対して、拡張子ベースのフィルタを適用する。

### 4.1 フィルター項目

- SVG を非表示にするチェックボックス
- GIF を非表示にするチェックボックス

### 4.2 判定基準

各画像カードには dataset.ext を持ち、URL の拡張子から取得する。

- ext が svg の場合、SVG フィルター対象
- ext が gif の場合、GIF フィルター対象

### 4.3 動作

- SVG 非表示チェックが ON の場合、svg 拡張子の画像を grid から非表示にする
- GIF 非表示チェックが ON の場合、gif 拡張子の画像を grid から非表示にする
- フィルター後の表示対象に沿ってモーダルの前後移動を同期する
- 現在のモーダル画像が条件外になった場合は一覧へ戻る。現在画像が残る場合は拡大・原寸の状態を維持し、前後の位置を更新する

### 4.4 実装方針

- フィルターは applyFilters() でまとめて評価する
- 各 item の display を none もしくは空文字で切り替える
- 画像の自然サイズが読み込み済みでない場合は、読み込み完了後に再度適用する

---

## 5. 最小サイズフィルター仕様

最小サイズフィルターは、一覧表示の画像カードを絞り込むための条件として機能する。

### 5.1 入力項目

- 最小横幅入力欄: min-width
- 最小縦幅入力欄: min-height
- 適用ボタン: apply-size-filter
- クリアボタン: clear-size-filter
- 初期値は横幅・縦幅ともに 400 とする
- 初期表示時点で、この初期値が適用済み（committed）の状態とする

### 5.1.1 適用中フィルター情報

- `filter-info` に現在適用中の最小サイズを表示する
- 表示形式は「適用中：横 ≥ {幅}px / 縦 ≥ {高さ}px」とする
- 初期表示時から、初期値に基づく適用中の最小サイズを表示する
- `visible-count` に一覧の状態件数を表示する
  - 表示中（必須）
  - 読み込み中（サムネ未完了。件数があるときだけ）
  - 失敗（サムネ読み込み失敗で除外。件数があるときだけ）
  - フィルター非表示（読み込み済みだが条件外。件数があるときだけ）
- 読み込み未完了のカードはサイズ未確定のため一覧に出さず、「読み込み中」として数える（フィルター非表示には含めない）
- SVG / GIF / 最小サイズフィルターの結果は「表示中」と「フィルター非表示」に反映する

### 5.2 ルール

- 0 以上の整数のみ入力可能
- 空欄は許容するが、実際の適用時には 0 として扱う
- 負数は入力不可
- e / E / - / 小数点などの不正な入力は入力時に弾く
- 実際に入力欄に残る文字列が不正だった場合でも、適用時に正規化する

### 5.3 実際のフィルター値

ビューアは入力中の値と適用済みの値を分離して管理する。

- 入力中の文字列: input 要素の value
- 確定済みの閾値: committedMinWidth / committedMinHeight

この分離により、入力途中で不正な値が入っても、実際のフィルター判定は確定値のみを使う。

### 5.4 確定処理

commitMinSizeFilter() は以下の流れで値を正規化する。

- 空文字 → 0
- 負数 → 0
- 整数でない値 → 0
- 非数値 → 0
- 正常な 0 以上の整数 → その値を保持

最終的に、入力欄の value も正規化済みの数値文字列へ更新し、committedMinWidth / committedMinHeight に反映する。

### 5.5 フィルター判定

各 item の判定は以下の条件になる。

- Number(item.dataset.width) < committedMinWidth → 非表示
- Number(item.dataset.height) < committedMinHeight → 非表示

両方が条件を満たせば表示、どちらかが条件を満たさなければ非表示になる。

### 5.6 反映タイミング

フィルターは次の操作で反映される。

- Enter キー押下
- 適用ボタン押下
- フィルター対象の画像読み込み完了時
- SVG / GIF チェック状態変更時

適用中フィルター情報と表示中件数は、次のタイミングで更新する。

- 適用ボタン押下時: 最小サイズと表示中件数を更新する
- Enter キー押下時: 最小サイズと表示中件数を更新する
- 画像の読み込み完了時: 表示中件数を更新する
- SVG / GIF チェック状態変更時: 表示中件数を更新する

クリアボタンを押下した場合は、入力欄の値だけを横幅・縦幅ともに 0 に戻す。
この操作ではフィルターを再適用せず、適用中の最小サイズと一覧の表示状態を保持する。

---

## 6. 入力制御仕様

### 6.1 入力時の制約

入力欄では beforeinput イベントを利用し、以下の入力を抑止する。

- -
- e / E
- 小数点
- 非数値文字

これはユーザー体験を優先した入力制御であり、ブラウザの number 入力の制限が不十分な場合の補助として機能する。

### 6.2 Enter 時の挙動

入力欄で Enter を押下した場合、以下を実行する。

- 入力値を正規化する
- 確定値を更新する
- applyFilters() を実行する
- 適用中の最小サイズ情報を更新する

### 6.3 空欄時の扱い

- 空欄状態は許容する
- Enter または適用ボタン押下時には 0 として確定する
- 初期表示時の入力値は 400 とする

---

## 7. 画面表示に関する制約

- SVG / GIF / 最小サイズのフィルターは表示状態に関係なく、一覧内の画像に対して評価される
- モーダルの表示対象と前後移動はフィルター後の一覧に同期する。現在画像が条件外または読み込み失敗で一覧から消えた場合はモーダルを閉じる
- モーダル表示中は背景に inert を設定するため、通常の操作で背景のフィルター入力を変更することはできない

---

## 8. 期待されるユーザー体験

- ユーザーは最小幅・最小高さを簡単に入力できる
- 不正な値を入力しようとする場合、入力時に抑止される
- 余計な数値入力や誤操作が起きにくい
- 現在適用中の最小サイズを確認できる
- 現在表示されている画像カード数を確認できる
- 一覧で必要な画像だけを効率的に見られる
- 一覧の絞り込みとモーダルの表示対象・前後移動が一致する

---

## 9. 実装上の要点

- セレクタは一覧カードとモーダル画像に限定して背景を適用する
- 画像の自然サイズの取得後にフィルターを再評価する
- 確定済みの閾値を使い、入力欄の raw value をそのままフィルタ条件に使わない
- 最終判定は committedMinWidth / committedMinHeight を基準に行う

この設計により、入力時の快適さと、最終適用時の安全性を両立している。
サイズフィルターは入力中の値と確定値を分け、入力時の抑止と適用時の正規化を組み合わせる。


## 10. キーボード操作とフォーカス

- 拡大・原寸・画像読み込み待ち中はEscapeでモーダルを閉じる。一覧表示中は左右キーとEscapeを奪わない。
- 左右ボタン・左右キーはフィルター後の一覧に沿って前後へ移動する。先頭・末尾の対応する矢印は隠し、範囲外へ移動しない。
- Alt・Ctrl・Meta付きの左右キーはブラウザーなどに任せる。Shift付きの左右キーは画像移動に使う。入力欄・選択欄・編集可能領域での左右キーは奪わない。
- モーダルを開くと閉じるボタンへフォーカスを移し、背景を inert にしてTab操作で背景へ移動しないようにする。閉じると背景の inert を解除する。
- 別画像へ移動すると拡大表示へ戻し、前画像の原寸・ドラッグ・位置をリセットする。
- 画像が画面に収まる場合、原寸切り替えボタンを隠し、画像クリックによる原寸切り替えも行わない。

## 11. レイアウトの保守

- 閉じる操作は右上、拡大・原寸切り替えは右下に配置する。ボタンの大きさ・背景・余白はCSS、記号の形状はHTML内のSVGで管理する。
- 操作ボタンは `5vh` と最小幅・高さを組み合わせる。SVGの `viewBox` と線幅を変更するときは、小さな画面でも記号が読めるか確認する。
- 原寸画像は表示寸法を `getBoundingClientRect()` で取得し、各軸の位置を `(windowの寸法 - 画像の寸法) / 2` で中央へ配置する。
- ドラッグ中は各軸の位置を画像端で制限し、画面内に収まる軸は動かさない。拡大表示へ戻ると原寸クラスを外し、left / topを0へ戻す。
